# 服务器迁移与训练

**2026-09-15 更新：**创新点一请优先使用 [创新点一_数据与训练.md](../创新点一_数据与训练.md) 中的迁移与 `meld_server.sh` 步骤。下方旧版 `smoke-features` 和通用训练例子仍是合成样例，不作为 MELD 正式训练输入。迁移需要另行复制 `data/raw/meld` 和 `models/pretrained/meld`；这些目录被 Git 忽略。

当前项目将新研究代码与原机器人 ROS 环境分开。Windows 只需 Python 即可回放和评测，服务器负责冻结编码器特征、训练及消融，机器人继续使用它匹配的 ROS/音频环境。

## 本轮已经验证的环境

- 离线核心：仓库 .venv，Python 3.9.13，无第三方依赖。
- 模型验证：D:\Anaconda\envs\DL\python.exe，Python 3.9.19、PyTorch 1.12.0+cu113，实际运算指定 CPU。
- 两个模型均完成小型合成特征的前向、反向、优化器更新、训练/验证和检查点保存；不代表在真实数据上收敛。
- 未验证本机 CUDA，也未修改显卡驱动。原有机器人代码需要独立环境和真实设备，不能直接用新 .venv 启动。

新服务器可选择 Python 3.10/3.11 的独立环境，并按 [PyTorch 官方安装页](https://pytorch.org/get-started/locally/) 选择与服务器驱动匹配的版本；不要照搬旧机器人依赖全集或直接复制 Windows 虚拟环境。

## 代码迁移

先将确认后的 biyelunwen 工作区提交并同步到可访问的远程，或者复制整个源代码目录。当前本轮修改尚未自动提交或推送，不能假定服务器 git checkout 就能拿到这些新文件。

服务器上的基本步骤：

```bash
git clone https://github.com/clusteramary/yqy_audio_main.git
cd yqy_audio_main
# 仅在该分支已推送后执行
git switch biyelunwen
python3 -m venv .venv
source .venv/bin/activate
python -m unittest discover -s tests -v
```

安装合适的 PyTorch 后执行 `python scripts/smoke_models.py`。先 CPU 验证，再把实验配置 training.device 改成 cuda；如尚无可用 GPU，仍可用 cpu 验证小数据。当前单样本训练器不启用 AMP、多进程或分布式训练，保证行为清晰；正式大规模数据需要再增加缓存分片和批训练，不能把它当作高吞吐训练平台。

data/raw、data/processed、data/features、outputs 和 checkpoints 已忽略，**不会随 Git 迁移**。数据单独复制，依据报告中的 SHA256 检查一致性。真实录音和专利原文不应随公开代码发布。GPU/系统环境差异可能影响结果，迁移后保存新的环境版本，不承诺跨平台逐位一致。

## 复现训练流程的小样例

以下均为软件测试，随机特征没有科学含义：

```bash
python scripts/make_smoke_features.py
python -m interview_robot train --train outputs/smoke-features/state/train.jsonl --validation outputs/smoke-features/state/dev.jsonl --config configs/state_model.json --output outputs/new-state-smoke
python -m interview_robot train --train outputs/smoke-features/ranking/train.jsonl --validation outputs/smoke-features/ranking/dev.jsonl --config configs/ranker_model.json --output outputs/new-ranking-smoke
python -m interview_robot evaluate-model --data outputs/smoke-features/ranking/dev.jsonl --checkpoint outputs/new-ranking-smoke/best.pt --output outputs/new-ranking-smoke/evaluation.json
```

在本机，将以上 python 换成 `& 'D:\Anaconda\envs\DL\python.exe'` 即可。输出目录必须是新建或空目录，避免覆盖其他实验。训练保存验证损失最小的 best.pt；独立评测输出指标和逐样本预测。检查点加载只用于可信的本项目训练产物。

## 正式数据到训练

1. 下载并保留数据的官方划分、许可证与原始版本。审计重复会话与候选冲突，确定协议，不先看测试分数改数据。
2. 在 data/processed 形成标准 JSONL。第一点必须先落实真实时间窗口标签；第二点先完成 FQ-Bank 文本基线，再建设只使用历史查询的知识检索。
3. 冻结编码器特征提取脚本现已针对 MELD 实现并用真实 MP4 验证，见 `scripts/meld_features.py`。这一条是旧规划的完成项；正式全量特征仍按新文档留到服务器生成。
4. 将 config 中 8 维示例输入替换成真实编码器输出维度，记录 encoder revision、截断长度、采样率、标准化参数、缺模态规则和提取时间。不得把随机特征用于正式训练。
5. 每个配置运行种子 42、43、44；仅依据验证集选模型。最终固定测试集一次性评估并汇总均值与标准差，同时保存所有种子的结果。
6. 状态模型消融 use_gate、use_temporal 和 modality_dropout；排序模型消融 use_knowledge、use_gate，并配合同批数据的知识扰动版本。先补简单融合、句向量和 Cross-Encoder 对照。
7. 模型定型后，再增加面向 robot_runtime 的推理服务/进程接口及特征缓存，测量真实端到端延迟。

实验报告包含数据 SHA256、配置、Python/PyTorch 版本、Git commit 与 dirty 标记。目前 dirty=true 表示用了未提交修改，正式实验前应建立可追踪提交。保存训练/验证记录，并在单独测试评测中报告真实任务指标，不只报告 loss 下降。

## 机器人侧衔接

robot_runtime 保留原脚本导入关系，按其独立说明启动。新增 LegacyKeywordAdapter 可输出与原 5557 端口匹配的 voice_keyword 消息，默认 dry-run；仍需上机核对动作库与实际含义。

新模型与原云端自由对话客户端尚未接通。接入时要指定唯一的回复控制者：当新排序器选择下一问时，语音侧应播报指定文本，不能让旧云端对话和新排序器同时自行提问。ASR、播放反馈、轨迹特征和模型推理需要共同 session_id/utterance_id；一轮失败通过显式恢复处理，不无限重复动作。
