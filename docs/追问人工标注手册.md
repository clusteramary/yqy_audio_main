# 追问人工标注手册

版本：2026-09-29 试标版。对象：`data/processed/followup-v2-mixed/kdconv/human_audit.jsonl`。这是弱标签质量审计，不是让标注者验证模型一定正确。

辅助入门示例见 [创新点二_AI初标示例与复核](创新点二_AI初标示例与复核.md)：6 段 dev 对话、60 条候选，全部是 AI 初标，真人字段仍为空。需要独立标注的人员不要预先阅读这些 AI 判断。该试标补充了陈述/问题类型和实体错配检查，尚未将其作为自动过滤训练数据的规则。

## 试标安排

2026-10-08 已生成 `data/annotations/kdconv_blind_review_50.jsonl`，含50个不同对话、500候选，未包含此前6段AI初标的对话。该文件隐藏弱标签、来源与AI判断；双方各自复制后填写 `human_annotation`。操作及一致性命令见 [本地持续开发交付](本地持续开发交付_2026-10-08.md)。原100段 human_audit 文件保持不变。

先取 30–50 个 dev 上下文，由两名标注者独立完成；隐藏 source、自动 relevance、模型分数和参考问题位置。已有 human_audit 文件已去除这些字段。两人使用相同样本与候选，不讨论后再回填“独立”标注；保留独立版和仲裁版。

当前文件字段 `human_relevance` 填 0–3，`repeat`/`answerable` 填 true/false；证据不够时保留 null，并另附说明。null 是无法判断，不能当作 0 或 false。可在候选下加 `depth`、`note`，前者 0–2。

| 维度 | 判断标准 |
| --- | --- |
| relevance=0 | 明显脱离话题、指代无法解析或前提明显冲突 |
| relevance=1 | 大致同领域，但与当前回答衔接弱或目的含糊 |
| relevance=2 | 能合理衔接并继续对话，可作为候选追问 |
| relevance=3 | 衔接明确且有针对性地推进当前谈话；不要求与原始下一问一致 |
| repeat=true | 已有历史实质回答了相同信息，再问没有明显澄清/比较目的 |
| repeat=false | 所需信息未被回答，或明确进行必要澄清；共享同一实体不算重复 |
| answerable=true | 根据当前主题、可见知识或正常受访者经验，问题有清晰可回应的含义 |
| answerable=false | 存在明显错误前提、矛盾指代或无法确定的要求；知识库没收录不自动判 false |
| depth=0/1/2 | 简单事实确认／解释或比较／对原因、影响、经历或观点的进一步探究；此维度需试标后修订 |

## 操作例子（人为说明，不是实验数据）

历史已经明确说“歌曲由甲作曲”，候选再问“是谁作曲？”通常是重复；“甲为什么采用这种编曲风格？”可能不重复，但 answerable 取决于对话主体能否回应。不能只因后一问更长就判更深入。

对原数据真实下一问，也允许给低分：真实对话可能有寒暄、反问、重复或转移话题。对采样负例，允许给高分：其未被选中不等于不合适。

## 试标后要报告

逐项给出有效标注数量、无法判断比例、完全一致率、相邻等级分歧比例；序数 relevance 可计算加权 Cohen kappa，并同时公布标签边际分布。不能只报一个 kappa 值而隐藏大多数样本同类的情况。当前没有收集真人标注，也没有宣称完成一致性测量。

汇总“弱负例被两人均判 relevance≥2”的比例与误差范围，分析领域/负例类型。若比例较高，采用多正例人工评价子集，或重构任务；不要继续把单一观察正例当完美真值。阈值、量表和采样方案在 dev 试标完成后冻结，test 标签不得参与修订模型。

中文机器人访谈必须另外采集少量会话、记录参与者授权与来源。公开影视、音乐、旅行聊天中的排序改善，不能替代访谈中的追问深度和用户体验证据。
