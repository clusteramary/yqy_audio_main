# 数据与标注规范

**2026-09-15：**MELD 的正式样本、7 类 emotion/3 类 affect 标签、历史窗口和特征定义见 [创新点一_数据与训练.md](../创新点一_数据与训练.md)。下文 `observations.jsonl` 是机器人观测/规则状态接口，不能把其中的 turn 标签规范套在没有接话真值的 MELD 上。

数据接口为版本 1，UTF-8 JSONL，每行一个对象。小样例见 data/examples，真实数据放 data/raw、data/processed、data/features，均默认忽略。所有时间戳采用同一会话内单调递增的秒数，不混用墙上时钟和设备相对时钟。

## 交互观察

必填字段为 schema_version、session_id、utterance_id、timestamp、robot_playing、modalities。模态缺失时省略该项，不伪造“中性/静音”。

- audio：timestamp、confidence、speaking。缺失音频不表示用户停止讲话。
- text：timestamp、confidence、text、final。必须对应当前 utterance_id；上一轮转写不能混入新一轮。final 表示 ASR 提交完整结果，不天然等于可接话。
- visual：timestamp、confidence，可选 speaker_id、affect。speaker_id 是当前会话的外部 face track/主说话人跟踪结果，不是跨会话身份识别结果。
- labels：可选人工真值，turn 为 HOLD/SHIFT/ROBOT/IDLE；affect 为 positive/neutral/negative。估计器只使用观测，标签仅供离线评测。
- ranking_id：只用于回放文件，关联某条候选问题场景。生产采集数据无需预先填入。

模态时间戳不能晚于观察时刻。超过 max_age_seconds 或低于 min_confidence 的证据不会进入规则估计。evidence_confidence 只是输入置信度，不是经过校准的输出概率。规则模型没有预测未知人物和潜在情绪的能力。

## 追问排序

每行包含 schema_version、id、group_id、dataset、split、history、knowledge、knowledge_source 和 candidates。

history 为截至当前轮的文本列表；knowledge 为决策时可获得的知识片段列表，可以为空。knowledge 非空时必须说明来源。每个候选含 id、text、relevance，相关性为整数 0–3：0 不适合、1 可接受、2 合适、3 优先。公共数据二值标签直接使用 0/1，不强行扩成四级。推理接口只接收 id/text。

需要至少两个不同候选、至少一个正例，候选 ID 和文本不可重复。FQ-Bank 适配器会剔除同标签重复候选，对同文字正负标签冲突的样本单独记录后隔离。元数据保存原始数量、变更与文件哈希。当前工具采用清理版协议；正式复现时还需决定是否同时保留原始候选协议报告，不能隐藏清理过程。

按完整会话/参与者划分，不能随机打散同一段对话里的窗口。validate-ranking 会检查样本 ID、group_id 和完全相同上下文的跨划分重叠；它不能发现语义近重复、同一受访者的不同 ID 或官方数据集的 ID 重编号，需要额外审计。

### 人工追问标注

标注者看到截至当前轮的对话、可获得的知识和随机排序候选，不看到模型分数。先标是否相关、是否重复、是否有知识依据，再给总体 0–3 分。对拒绝继续某话题的显式表达，应记录为独立观测，不能仅凭 negative 情绪标签推断不愿继续。

先用 30–50 条试标，让两人独立完成，整理分歧例子并修订手册。正式数据保留两份原始标签和裁决标签，报告一致性。几百条是系统扩展实验的初步规模设想，不代表足以训练所有任务，也不是已采集数量。

## 神经模型特征缓存

本轮模型吃缓存特征，不直接读取音视频。每条样本额外要求 task、dataset、split、id、group_id、feature_source；feature_source 应包括编码器名称、权重版本、窗口配置和归一化版本。输入维度必须和模型配置一致。

### 状态模型

- features：按 configs/state_model.json 的 input_dims 顺序命名，每模态为 [T,D_m]。
- available、confidence、age：均为 [T,M]；available 为布尔，confidence 为 0–1，age 为非负秒数。
- labels：turn 为 0=HOLD、1=SHIFT；affect 为 0=positive、1=neutral、2=negative；speaker_change 为 0=未变、1=切换。**缺失标签填 -100**，不能填 0 伪装负例。
- 每条样本预测其历史窗口最后一个有效时刻；模型支持长度参数屏蔽尾部 padding，训练脚本逐样本读取，无需人工补长。
- 跨数据集不统一人物身份号；ROBOT/IDLE 留在外部系统状态，不使用此二分类头表示。
- 同一条样本至少有一个监督标签，不从规则输出生成“人工真值”再用于宣称模型超过规则。

### 排序模型

- history_features：[L_H,D]。
- knowledge_features：[L_K,D]，缺失知识允许空列表。
- question_features：候选列表，每个候选 [L_Q,D]，长度可不同。
- relevance：与候选顺序一致的 0–3 标签；可附 candidate_ids 与标准化数据 ID 对应。
- 编码候选时只编码问题文字，不能把答案、relevance、负例 reason 放入编码器输入。
- 训练脚本自动补齐问题长度；模型内部的 mask 隔离补齐内容。无知识时精确退回对话分支。
- 当前网络是固定编码器之上的轻量注意力排序器，不是已经训练好的 BERT Cross-Encoder；后者属于待补的对照方法。

缓存必须保存源样本 ID 和划分，先划分再拟合归一化或训练编码器。检索索引与词表仅使用允许访问的语料；测试标签、未来回答和未来检索结果不能进入特征。feature_source 目前是说明字段，软件不会自动证明特征没有泄漏，制作者需要保留提取脚本和日志。

## 真实机器人采集

建议一条会话清单关联：匿名参与者 ID、会话 ID、设备与模型版本、开始时间、音频/图像路径、采样率、时钟同步偏移、ASR 部分结果时间、播放开始/结束、动作索引及返回状态。不要仅保存终端打印，后续很难重建时间因果关系。

第一点的真值须有明确的标注时刻和轮次规则；自采时可由两名标注者基于完整记录确定边界，但模型输入必须截断到当时可观测的过去。保留原始数据与标注版本，导出的匿名数据单独存放。
