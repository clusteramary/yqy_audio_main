# 毕业论文开发与实验计划

**历史文档提示（2026-09-29）：**本文保留早期方案，其中 HOLD/SHIFT 研究安排、仅下载 FQ-Bank dev 等描述已经过时。当前唯一总规划为 [硕士论文研究与迭代规划](硕士论文研究与迭代规划.md)；点一为句末情感，点二采用修订候选协议，第三部分是系统验证。不要按本文旧版实验矩阵直接启动训练。

**2026-09-15 实施更新：**创新点一已落实为 MELD 上的句末情绪/情感状态估计与缺失模态实验，完整方案见 [创新点一_数据与训练.md](../创新点一_数据与训练.md)。不使用 MELD 构造 HOLD/SHIFT 标签。下文是此前规划，其中第一点“先寻找轮次预测数据”的安排已收敛为本次方案；第二、三点继续保留。

建议暂定题目为《面向采访机器人的多模态交互状态估计与知识增强追问方法研究》。现在先固定数据接口和实验边界，不急于把模型结构写成最终创新结论。三个点形成“理解交互状态、选择下一问、机器人执行”的主线。

## 一 三个点的范围

| 点 | 要验证的假设 | 本轮实现 | 后续验收条件 |
| --- | --- | --- | --- |
| 一 置信度感知时序多模态状态估计 | 置信度、缺失标记与历史窗口能改善含噪/缺模态条件下的状态估计 | 特征投影、模态注意力、置信度和年龄衰减门控、GRU、多任务分类头 | 在同一数据划分上优于单模态和简单融合，并报告退化条件与开销 |
| 二 知识增强多轮追问排序 | 可在决策时获得的知识有助于区分相关但不合适的候选问题 | BM25、问题条件双路注意力、知识门控、listwise 损失 | 同候选集下对比 dialogue-only 与知识增强，并通过知识消融排除泄漏 |
| 三 机器人本体与交互系统验证 | 状态与排序结果可在机器人上稳定执行 | 保留相机、实时语音、ROS 音频、UDP 索引代码，新增离线流程控制与协议适配 | 真实设备上验证延迟、重复动作、抢话和会话恢复等表现 |

本轮没有增加独立五分类 Agent，也没有把强化学习、VITS 训练或通用规划列入必须完成的任务。第三点作为系统实现与应用验证章节：单纯“有机器人本体”不足以支持方法创新，需呈现你完成的闭环设计、交互机制和整机实验证据。

创新点一优先收敛为 HOLD/SHIFT；ROBOT 是播放反馈，IDLE 是系统缺乏有效交互证据的状态，二者无需硬当成同一个学习任务的类别。当前模型附带情绪和说话人切换头，有标签才训练。轨迹 ID 来自跟踪器，不把不同数据集中的人物 ID 拼成跨数据集分类任务。

创新点二的主实验只依赖对话、知识和候选问题。情绪/参与状态对排序的修正放到自采机器人数据的扩展实验；不强制公共文本数据具备不存在的多模态标签。

## 二 现在在本机做什么

本机检测结果为 GTX 1650、4096 MiB，驱动 462.30；与口述的 1060 不同。本轮代码验证全部使用 CPU。实际可运行的开发环境为独立 Python 3.9 虚拟环境；模型小样例使用已有 DL 环境，没有改驱动或安装大型训练框架。

优先级顺序：

1. **整理代码和跑通离线链路**：本轮已完成。旧机器人代码移到 robot_runtime；历史版本、编译缓存、样例媒体和无效 DeepFace gitlink 移出工作区。Git 历史与仓库外归档都可恢复。
2. **完成数据审计**：FQ-Bank dev 已转换并跑通 BM25；下一步核对 train/dev/test 的会话 ID 是否跨文件重编号、重复上下文与候选冲突，冻结正式评测协议。不要仅靠在 ID 前加 split 来掩盖跨划分重复。
3. **确定第一点的数据来源和标注口径**：先取得可用样本并查看时间戳、说话人轨迹和轮次事件，再最终决定主任务。若两周内没有可用的因果轮次数据，就把第一点正式收敛到“缺失模态下的情绪/交互状态估计”，把接话规则留在系统中，避免同时承诺三个没有标签的预测任务。
4. **准备知识材料和标注工具输入**：整理可公开的领域文档，按段落记录 source_id、实体、版本和时间；准备几十条采访上下文供两名标注者试标候选追问质量。先确认标签一致性，再扩大规模。
5. **持续使用人工数据回放边界事件**：用户犹豫、ASR 部分结果、画面丢失、播放反馈滞后、重复 SHIFT、换人。每修一个真实问题补针对性测试。

这些任务基本不受 GPU 限制。大规模音视频特征提取、编码器微调和批量训练留到服务器。

## 三 数据选择与不能混用的地方

| 数据/来源 | 适合验证 | 使用边界与当前进度 |
| --- | --- | --- |
| FQ-Bank | 多轮追问候选检索/排序 | 英文信息获取对话，不等于中文机器人采访；已读取官方格式并下载 dev |
| KdConv | 中文对话与知识增强的辅助实验 | 真实下一句不一定是问题；需要筛选、标注或明确改成下一句排序任务 |
| MELD | 多模态情绪/情感子任务 | 情绪标签不能替代接话、意愿或真实说话人定位标签；三分类应采用明确的 sentiment 映射 |
| AVA-ActiveSpeaker | face track 是否发言 | 可作为感知组件数据，不能直接冒充全套 Speaker/Turn/Affect 联合标签 |
| VAP 与轮次预测相关数据 | 音频轮次预测参照 | 方法代码不等于免费可用的训练语料；要确认语料访问和双方声道条件 |
| 自采机器人采访 | 跨模块联动、系统闭环与中文域适配 | 先小规模试采，按参与者/会话分组，保留授权、时间同步和标注版本 |

依据：[FQ-Bank 论文](https://aclanthology.org/2023.findings-eacl.149/)、[官方数据格式](https://github.com/amazon-science/fq-bank)、[KdConv 官方仓库](https://github.com/thu-coai/KdConv)、[MELD 官方仓库](https://github.com/declare-lab/MELD)、[AVA 论文页](https://research.google/pubs/ava-activespeaker-an-audio-visual-dataset-for-active-speaker-detection/)、[VAP 作者代码](https://github.com/ErikEkstedt/VoiceActivityProjection)。以上按 2026-09-14 可访问内容核对。

不要把多套不同人的文本、音频、视觉简单拼为同一条多模态样本。不同数据集可分别评测子任务，或用缺失标签损失进行有明确依据的多任务训练。只有具有同一事件完整真值的数据，才能计算联合状态正确率。

## 四 正式实验矩阵

### 第一部分 状态估计

主任务先确定预测时刻 t、历史窗口长度 L 和预测范围 Δ。例如先试过去 2 秒观测，预测未来 500 毫秒内能否接话；这些数值是待验证的超参数，需和标注规则一起冻结。

对照顺序为音频单模态、文本单模态、视觉单模态、拼接 MLP、无门控融合、带门控融合、去时序版本和完整方法。当前 use_gate/use_temporal 配置支持部分消融，其他对照尚待实现。

所有输入必须在时刻 t 已经可获得：ASR 用截至 t 的部分转写，视觉/音频只取过去窗口；不能用最终整句转写预测之前是否说完，也不能让离线双向编码器看到窗口之外的未来信号。记录特征提取可用时间，而不仅是录制时间。

主指标：HOLD/SHIFT Macro-F1、SHIFT Precision/Recall、提前插话率、响应延迟。情绪另外报告 Macro-F1；说话人切换用二分类 F1，若另做 active-speaker 检测才采用相应 mAP。系统状态抖动率仅与真实切换率一起分析，不能把“从不切换”当成改进。

退化实验：固定种子和相同样本，分别屏蔽音频/文本/视觉、加入不同遮挡或噪声程度。训练用 modality dropout，测试时关闭随机 dropout；不要在每个模型上生成不同的测试扰动。当前 age 表示特征距当前采样点的年龄，门控只是待验证假设，不是已证明创新。

### 第二部分 追问排序

先完成 FQ-Bank 的文本排序：候选集 BM25 → 冻结句向量 → Cross-Encoder。双路模型必须在同一协议上评测。FQ-Bank 原始转换后 knowledge 为空，不能因此声称完成了知识增强实验。

知识实验使用固定知识库，通过**历史对话**检索 K，再对同一候选集打分；检索模块不能看到正确下一问的答案、未来回复的知识标注或候选正负标签。KdConv 当前轮未来 attrs 只可用于明确标注为 oracle 的上界分析，不可作为常规输入。

至少比较：无知识、等量检索知识、随机知识、打乱/错误实体知识、去知识门控、完整知识门控。无知识和有知识模型使用相同历史、候选、种子和训练预算；同时说明参数量差异。状态增强只有在自采数据有对应标签后再做。

指标：MRR、Recall@1/3、nDCG@3；多正例时 Recall 的分母是全部正例数。中文知识辅助集如果选择“下一句”而非“下一问”，单独列任务和表格，不能混报。

候选池既决定难度也影响分数，必须冻结大小、去重规则和负例类型。BM25 目前是候选集内 IDF 的简单基线，不是原论文作者实现，也不是检索整个语料库的复现。

### 第三部分 机器人本体实验

建议先做 5–10 次试运行验证采集链路，再依据试验波动和可招募条件确定正式人数，不预先承诺统计显著。正式比较“已有规则系统”和“接入前两点的系统”；必要时增加只接入第一点/第二点的条件，平衡受试顺序和话题顺序。

记录用户结束到机器人首音频的延迟、意外插话次数、重复问题率、动作触发次数/重复次数、掉线次数、会话恢复时间和任务完成率。主观评价至少覆盖自然度、追问相关性和交流负担，评分规则在实验前确定。每个例子的原始记录应能回查到模型版本、输入状态和选中的问题。

本轮离线状态机能验证处理期锁定、播放反馈与冷却、同一轮只提问一次。它不能证明声学回声消除、ROS 延迟、模型服务器稳定性或真实动作完成效果，这些必须上硬件验证。

## 五 阶段交付与停止条件

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 当前 本机开发 | 数据规范、离线回放、基线、模型原型、测试 | 本轮已交付，见本次开发验证 |
| 数据准备 | 数据清单、划分、知识来源、标注手册、试标一致性 | 能提供真实训练与验证样本；第一点主标签来源落实 |
| 服务器恢复后 | 冻结编码器特征、三种随机种子、基线与消融 | 正式测试集保持封存；仅用验证集选模型和阈值 |
| 机器人整合 | 新模型推理接口、播放反馈和动作适配、真实日志 | 离线回放与硬件协议均通过，重新核对输入输出音频格式 |
| 论文写作 | 原始结果、均值和波动、失败分析、可复现命令 | 结论只覆盖实际证据，保留负结果，不用合成示例支撑性能结论 |

推荐研究顺序是**先第二点的文本数据与基线，再落实第一点标签，随后服务器训练，最后统一上机器人**。这是开发顺序；论文仍按状态、追问、机器人系统来组织。前两点的名称和结构可随真实结果调整，但数据划分、实验协议和原始记录一经用于正式比较就应版本化保存。
