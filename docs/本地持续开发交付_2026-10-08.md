## 2. Cross-Encoder 方法正文补充

对候选 c_j，将历史 H 的最近八句话与候选文本组成联合输入。历史内部以分隔 token 保留话语边界，构造 `[CLS] H [SEP] c_j [SEP]` 或编码器相应的句对格式。编码器与标量分类头共同产生 s_j，训练时全部可训练参数参与优化，使用现有多正例分级 listwise loss。标签只进入损失，不进入分词或推理接口；外部知识不进入此 history-only 基线。

当前配置最大长度 512 tokens，候选保留前 96 tokens，其余预算保留历史末尾；同一组所有候选共享相同历史可见范围，但长候选占用更多预算。候选组为 batch 的单位，默认每批一组，组内全部候选同时打分，补齐候选分数为负无穷。训练按 dev MRR 严格提高时保存最佳检查点，patience=3，最多10轮，AdamW 学习率 2e-5。train 入口只读取 train/dev，不读取 test。

此基线与冻结句向量模型使用相同样本/候选、最多八句历史，但 token 预算与参数更新方式不同：冻结模型每句单独编码，Cross-Encoder 受联合512长度限制。论文必须记录各自截断比例和计算预算，不能直接声称“完全相同输入 token 的消融”。将其定位为较强的可微调对照；严格预算匹配比较仍需单独配置并统计。

中文配置使用本地 bert-base-chinese，参数量 102,268,417；英文配置使用本地 distilbert-base-uncased，参数量 66,954,241。英语版本应称 DistilBERT Cross-Encoder，不能写成复现 BERT/RoBERTa 原表。方法定位参考 [FQ-Bank 官方论文](https://aclanthology.org/2023.findings-eacl.149/)，该论文建立了多轮候选追问排序基准；本实现采用当前清理协议和自定义训练设置。

保存 `best/` 中的模型、分词器与 `run.json`，记录源编码器、数据、实现及检查点哈希。评测拒绝检查点哈希不匹配、跨数据集协议和改动后的 dev；test 在最终协议冻结后显式传入。模型没有实现概率校准，分数不应直接作为“好问题概率”或拒选阈值。

先完成 KdConv 任务定义与标签审计，再决定是否将 v2 作为弱监督辅助实验；不能把“预检查可运行”当作“数据金标准已完成”。FQ-Bank 可按现有清理协议独立安排训练。

```bash
# 示例单种子。正式比较再运行 2026、3407，使用各自新目录。
python scripts/cross_encoder.py train --config configs/cross_encoder_fqbank.json --device cuda --seed 42 --output outputs/cross-fqbank/seed42
python scripts/cross_encoder.py evaluate --checkpoint outputs/cross-fqbank/seed42/best --input data/processed/followup/fq-bank/dev.jsonl --device cuda --output outputs/cross-fqbank/seed42/dev
# 仅在冻结协议后执行 test。
python scripts/cross_encoder.py evaluate --checkpoint outputs/cross-fqbank/seed42/best --input data/processed/followup/fq-bank/test.jsonl --device cuda --output outputs/cross-fqbank/seed42/test
```

KdConv 将配置替换为 `configs/cross_encoder_kdconv.json`，输入目录替换为 `data/processed/followup-v2-mixed/kdconv`。本轮没有执行这些训练命令。模型/数据路径按仓库根目录解析，因此应从仓库根目录启动；迁移时安装 requirements-followup 中的环境并迁移已校验的模型文件。

## 3. 候选预警发现与后续处理

| 划分 | 对话上下文数 | 候选出现次数 | 任意预警 | 仅“呢”等缺明确疑问线索 | 与历史完全相同 |
| --- | --- | --- | --- | --- | --- |
| train | 29,488 | 294,880 | 18,207 | 17,867 | 64 |
| dev | 3,767 | 37,670 | 2,680 | 2,405 | 4 |

候选会在多个上下文重复出现，因此表中统计的是出现次数，不是唯一文本数。不同预警类别会重叠。疑问代词也可能出现在陈述句中；没有问号也可能是合法问题；末尾“呢”既可能提问也可能陈述。故本轮没有自动过滤、改正负标签或重建候选协议。

检索知识中泛称主体预警条目为 train 17,597、dev 2,094，主体包括“专辑”“出生”“音乐人”等。此规则只提示消歧风险，不认定所有此类知识错误。完整预警及前100个例子保存在 `kdconv_train_candidate_audit_2026-10-08.json`、`kdconv_dev_candidate_audit_2026-10-08.json`。

盲标包按领域尽量均衡取样，每段来自不同完整对话，不适合直接估计原始总体问题比例。标注者复制盲包为各自文件，在候选的 `human_annotation` 内填写字段，完成后将 status 设为 reviewed 并填个人 reviewer_id。保留不了解/不确定为 null；待定项不当作负标签。两名独立标注者不互看文件和 AI 初标。

```bash
python scripts/audit_annotation.py agreement --input data/annotations/reviewer_a.jsonl --second data/annotations/reviewer_b.jsonl --output outputs/annotation-agreement.json
```

上述 reviewer 文件需要实际人工创建，目前不存在。本命令检查候选/上下文一致性与不同标注者ID，对双方已完成且有效的 relevance 计算一致率、边际分布与二次加权 kappa；depth 同样使用二次加权，repeat/answerable/utterance_type 使用未加权 kappa。各维度分别报告有效成对数，不把 null 当 false。全相同单一类别导致期望分歧为零时返回 null，而不是虚构完美 kappa；未完成数量始终单报。

## 4. 请求确认控制器

新控制器与原 `InterviewController` 并存，旧回放兼容性不变。它显式绑定 session_id，每次 ASK 生成新的 request_id。started/finished/failed 必须匹配当前请求、会话、事件序号与状态；外来的、重复或乱序事件只记日志，不推进执行。

默认开始确认超时5秒，播放完成超时60秒；这些是工程初始值，尚非实测阈值。超时发生在调用 `tick()`、`step()` 或 `feedback()` 时，应用必须周期调用 tick，不能误认为本类自带后台看门狗线程。反馈时间使用本地收到事件的单调时间，严格递增；不要直接混用远端墙钟。

发生超时进入 FAULT，不自动重新发送。操作员确认播放已停止后，带理由调用 recover，经过冷却恢复；已处理话语和已问文本记录保留。排序器异常、越界候选或非有限分数进入故障态。同步 rank 调用本身尚无可中断超时，需要后续服务层支持；候选语义重复与低质量拒选也尚未解决。

```powershell
.venv-meld\Scripts\python.exe scripts/replay_confirmed.py --output outputs/my-confirmed-replay
```

本轮已执行版本输出在 `outputs/confirmed-replay-2026-10-08/`：3次模拟请求、14条事件，最终停在有意注入的结束确认超时 FAULT。最终故障态是测试预期，不是机器人真实故障。该脚本不发声、不发送UDP。

获得真实训练检查点后，可加 `--checkpoint outputs/cross-fqbank/seed42/best` 走 history-only 神经排序适配器；默认仍是 BM25。例子中的问题是英文合成数据，仅测试接口，不用于比较模型效果。适配器在只有一个候选时直接返回该候选的零分，不把它当作模型推理结果。

当前可写入论文的是方法和工程实现、真实数据审计以及软件性质验证。正式效果表、贡献有效性及用户体验结论仍为空。没有提交或推送本轮变更。
