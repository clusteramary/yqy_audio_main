## 本轮先做什么

1. 盘点代码、数据与专利/论文设想，区分实现、验证和假设。
2. 查阅相关原始论文，判断已有结构与可能研究贡献的边界。
3. 优先修复会损害实验可信度的问题：输入时序、候选标签捷径、消融公平性、统计单位与结果可复现性。
4. 在本机完成无训练数据诊断、协议工具、回归测试；不做全量特征提取和 GPU 训练。
5. 写研究问题、方法章节草稿与实验设计，保留结果占位，不伪造数据、用户实验或创新结论。

## 暂定主线

《面向智能交互机器人的鲁棒多模态情感感知与知识增强追问方法研究》。第一点明确为句末情感识别，不承诺 MELD 没有标签的接话预测；第二点是追问选择，不把候选排序等同于自主生成；第三点是系统闭环与应用验证，机器人本体本身不是算法原创贡献。

研究性来自可反驳的假设、公平对照、可靠数据与明确适用条件，不能靠堆叠模块或凑三个新名称保证。最终题目与学校要求需结合导师意见确定。

## 研究问题与可反驳假设

### RQ1 质量不可靠时如何保持情感识别的有效性

当前质量指标是截断比例、音频削波/静音、图像对比度，并非校准概率。离线 age 全为零，因此现阶段不能证明异步新鲜度机制有效。全帧 ResNet 也不是目标说话人的面部表情编码器。

建议第一点进一步聚焦：**质量代理存在偏差时的多模态情感融合与选择性输出**。研究完整观测、缺模态、连续传感器掉线和“质量代理与真实质量不一致”的情况，比较准确性与置信度可靠性。已有门控作基线，不急于命名新网络。

假设 H1：在统一特征与训练预算下，考虑缺失信息和经验证的质量信息，能够降低特定退化条件下的错误，同时不过度提高错误预测的置信度。反证条件：只在干净条件提升、缺模态退化更快，或 ECE/NLL 变差、所谓质量信息不优于全一质量。

设计路线：先加质量置常数/打乱/反转的评测；再决定是否值得开发质量可靠性预测或保守残差融合。若质量代理没有信息量，删除这一贡献主张，转向缺失模式与历史利用。温度缩放、模态 dropout、位置编码都属于已有技术，不能单独声称原创。

### RQ2 在无标签捷径的条件下知识是否真的改善追问

本轮发现并修正 KdConv v1 的候选来源捷径：不看对话的“未见问题优先”规则 dev MRR=0.927。v2 混合候选中同一诊断为 0.285，随机排序解析期望为 0.293。该修正只是必要的实验基础，不是新追问算法的性能提升。

建议第二点聚焦：**已谈内容覆盖与知识可靠性约束下的多轮追问选择**。区分相关性、重复性、可回答性、追问深度，不能用词汇重叠或单参考下一问代替全部指标。

假设 H2a：在同一候选协议、同一历史窗口和强语义基线下，知识能带来可复现的排序改进。H2b：覆盖信息降低人工判定的重复率，同时不明显损害相关性。H2c：无关/缺失知识时，可靠性机制优于无条件融合。当前只具备检验部分 H2a 的代码；H2b 需要人工多维标签，H2c 还需更强机制与验证。

反证条件：优势仅存在于特定负例构造；去知识后不变；仅靠候选身份/长度获得相同提升；覆盖模块改善 MRR 却增加人工判定的重复。此时应修订假设而不是扩大结论。

### RQ3 前两点能否在机器人上形成可测量的闭环

第三点按“系统设计与实验验证”组织。把状态观测时间、模型输出时间、请求/播放确认/动作完成时间写进可追溯日志。比较规则系统、只接点一、只接点二、两者接入；顺序和话题平衡。不得把 MELD 的情绪分数解释为真实用户内心或接话意愿。

既有专利提供模块化交互、上下文与动作索引、半双工控制等应用背景。专利写有改进 VITS，但当前仓库缺相应网络与实验材料，暂不列为本论文第四项训练贡献。专利技术描述、已实现代码和实验结论须分别列证据。

## 迭代顺序与停止条件

| 迭代 | 目标与交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0 本轮已完成 | 数据捷径审计、v2 候选、历史位置修正、校准诊断指标、对话分组区间、论文草稿 | 回归测试通过；保留 v1 与 v2 校验和；不使用 test 调参 |
| 1 本机下一轮 | 双人试标 30–50 个 dev 上下文；Cross-Encoder 同候选强基线训练入口；质量代理扰动协议 | 标注分歧原因可解释；模型与数据接口测试通过 |
| 2 本机 | 冻结候选/负例协议、标注手册与实验清单；加入无知识/打乱/恒定质量对照；系统故障回放 | 无明显来源捷径；无未来输入；实验预算一致 |
| 3 服务器 | 全量特征 → 单种子排错 → 固定三种子正式消融 | 仅 dev 选模；完整记录参数量、时间、数据/代码哈希 |
| 4 正式评测 | 冻结方案后测试、按对话区间估计、失败案例与人工审计 | 不因 test 分数重新挑协议；报告负结果 |
| 5 机器人与写作 | 小规模设备试跑、正式用户实验、跨域验证、图表和讨论 | 实验人数按试点方差/可招募条件确定，不预承诺显著 |

每轮只增加可解释的机制。先消除实验问题，再训练一个足够强的基线，再决定是否需要新结构。不要同时开展语音合成、强化学习、轮次预测、人物识别和问题生成等多条未标注任务。

本轮已生成 `data/processed/followup-v2-mixed/` 与 `data/processed/followup-v2-random/`。保持原始 `data/processed/followup/` 不变。两版都保持原 train/dev/test 样本数；只改 KdConv 候选负例来源，不改历史、正例、知识检索输入或标签含义。

新机器重建（目标目录必须为空）：

```bash
python scripts/prepare_followup.py --download
python scripts/prepare_followup_v2.py
python scripts/prepare_followup_v2.py --hard-negatives 0 --output data/processed/followup-v2-random
```

正式神经实验默认配置已指向 v2 mixed，不能再运行 KdConv v1 正式训练。v2 random 是候选难度敏感性分析：可先将同一个 mixed 训练出的模型评估在 random dev 上；如另行训练 random，则必须单独标注训练协议和输出目录。更换候选文件必须重建特征缓存，禁止沿用旧缓存哈希。
