## 二 真实数据的诊断证据

在完全相同的 3,767 个 KdConv dev 上下文中，比较“没出现在训练正例池里的候选优先”规则。该规则不读取 H/K、不训练，仅利用候选文本是否见过。

| 诊断项 | v1 | v2 mixed | v2 random |
| --- | ---: | ---: | ---: |
| dev 正例在训练问题池出现率 | 10.35% | 10.35% | 10.35% |
| dev 负例在训练问题池出现率 | 100.00% | 5.46% | 8.07% |
| 未见候选优先 MRR | 0.9270 | 0.2848 | 0.2855 |
| 均匀随机 MRR 解析期望（10 候选、1 正例） | 0.2929 | 0.2929 | 0.2929 |
| history-only BM25 MRR | 0.2105（前轮记录） | 0.2234 | 0.4059 |

v2 大幅削弱了已发现的来源捷径，但不是“无偏数据”的证明。v2 mixed 与 random 的 BM25 差异表明负例难度会显著改变基线表现。不能跨协议比较分数并宣称模型改进。成员关系捷径诊断只用 train/dev；test 仅重建候选和检查结构/哈希，没有计算其排名成绩或用其选方案。

补充：FQ-Bank dev 的同类诊断 MRR 为 0.1467，接近前轮随机期望 0.1549，本轮未发现同样规模的来源捷径；这也不代表不存在其他偏差。

## 三 v2 改变了什么

每个官方划分独立构造同领域问题池，负例来自不同完整对话；排除与正例/历史归一化相同的文本。mixed 尝试选四个词汇相似负例，再随机补齐九个；random 九个全部随机。候选仍按文本哈希排序，正例位置不固定。弱正例为观察到的下一问，未增加人工真值。

训练样本只由 train 建池；dev/test 池只用于确定固定评测候选，这是离线重排基准的构造，不是训练输入，也不是在线可用候选召回方法。此范围必须在论文中公开。正式机器人候选池应另外实现和评价。

新旧数据目录隔离，样本数均保持 train=29,488，dev=3,767，test=3,818。新目录分别为 `data/processed/followup-v2-mixed/`、`data/processed/followup-v2-random/`，各有输入和输出哈希清单；不会覆盖 v1 或原始数据。

## 五 本轮验证与不代表什么

执行 `python -m pytest tests -q`，当前 63 项通过；两个真实本地文本编码器均跑通小样例缓存、随机排序头保存/加载及前向。没有执行参数优化式语料训练，没有全量特征提取，没有调用云端付费接口，没有启动机器人设备。

新增回归覆盖：候选排除同对话、诊断拒绝 test、概率分布/平局覆盖、配对 ID 对齐/分组、位置顺序与补齐、统一历史范围、评估不改变随机流、打乱知识跨对话。构造反例的测试通过证明特定代码性质，不能证明论文算法有效。

结构化结果保存于 `docs/研究审查验证_2026-09-29.json`；完整运行结果位于 `outputs/research-review/`。本轮未 commit/push；先前未提交的创新点二工作保留，没有重置或删除。
